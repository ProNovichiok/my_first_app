# Запуск настоящего сервиса

## 1. Заполнить сведения

В `config/company.json` указать реального оператора/арендодателя, ИНН, ОГРН/ОГРНИП при наличии, адрес, контакт для обращений по данным, банковские реквизиты и точное место выдачи. Параметры возраста, стажа, пробега, доплаты — условия бизнеса, а не универсальные требования закона.

В `config/cars.json` заменить вымышленные машины на реальные: цену, залог, VIN, госномер, СТС и страховой полис; `demo:false`. Проверить право сдачи автомобиля, действующее ОСАГО и допуск водителя. Заменить SVG на свои законно используемые фотографии; при изменении id обновить путь изображения в public/app.js.

Выдуманные реквизиты нельзя использовать для настоящих договоров.

## 2. Документы и организация работы

Пройти пункты docs/LEGAL.md, согласовать договор, политику и отдельное согласие под фактический процесс. Определить сроки хранения договоров, бухгалтерских документов и резервных копий, законные основания каждой операции, порядок реализации прав субъекта, удаления и реагирования на инциденты. При изменении текстов увеличить consentVersion/privacyVersion.

Заполнить пробелы проекта договора: полномочия, основание владения, расчёты, срок возврата залога, страховые условия, обслуживание и согласованное продление. Проект генерируется в двух экземплярах с актами; без подписей договор не считается подписанным системой.

Оценить использование Telegram, включая идентификатор клиента и переписку. Прямой сбор паспортов в боте отключён, но это не освобождает от оценки трансграничной передачи и других требований к оператору.

## 3. Размещение в РФ

База, первичный сбор, документы и резервные копии должны размещаться в РФ с учётом применимых требований. Не используйте GitHub Actions, Pages, публичные репозитории и зарубежные облака для клиентских документов.

Вариант А: российский VPS с Linux, Node.js 24, HTTPS reverse proxy и supervisor/systemd.

Вариант Б: Docker Compose на сервере в РФ:
- Установить Docker и Compose из официального источника.
- Скопировать только исходники, `npm run setup` выполнить в доверенной среде либо создать секреты самостоятельно.
- Создать `data/` и `private/`, дать права uid 1000 (пользователь node в контейнере), закрыть доступ остальным.
- В `deploy/Caddyfile` заменить rental.example.invalid на свой домен. Настроить DNS на сервер.
- В `.env`: PUBLIC_URL=https://ваш-домен, DEMO_MODE=false, LEGAL_READY=true, BOT_TOKEN=новый-токен, BOT_ENABLED=true.
- LEGAL_READY — утверждение владельца о выполнении требований, а не автоматическая правовая проверка.
- `docker compose up -d --build`. Наружу открыты только 80/443; порт приложения не публикуется.
- TRUST_PROXY=1 допустим только за одним доверенным reverse proxy; при прямом запуске оставить 0.
- Проверить HTTPS, резервирование, журнал, форму и реальную генерацию файлов.

Вариант В: Windows-компьютер в РФ. `start.cmd` запускает сайт локально. Для доступа клиентов нужен собственный HTTPS-домен и правильно настроенный reverse proxy к localhost:3000. Компьютер должен быть включён. Проброс через зарубежный туннель не является готовым решением для персональных данных. Закрыть .env, data и private правами NTFS, включить BitLocker по возможностям устройства.

## 4. Бот и токен

Переданный в переписке токен рекомендуется перевыпустить через @BotFather; новый хранить только в .env. Не помещать токен в код, коммиты, изображения, README, клиентский JS или GitHub Actions.

Проверка токена возможна методом getMe; она не запускает бота. Программа при старте дополнительно проверяет username и наличие webhook. Если есть старый webhook или polling, сначала установить, кто его использует, и остановить старую интеграцию. Программа сама его не отключает.

Бот /start <случайная-строка> связывает заявку и выдаёт защищённую ссылку, /status показывает последние пять статусов. Бот принимает только личные чаты. Свободные сообщения не сохраняются приложением; фото не загружаются. Telegram как платформа может хранить присланные пользователем сообщения — запретить это кодом невозможно.

При статусе confirmed/active/completed/cancelled приложение отправляет уведомление в связанный чат, если бот включён. При первоначальной анкете клиент получает подтверждение на странице. Документы и Excel в Telegram не отправляются.

## 5. Работа владельца

1. Войти на /admin.html по ADMIN_TOKEN из .env.
2. Проверить анкету и оригиналы документов. Кнопка договора выгружает полный проект с реквизитами арендатора, поэтому выдавайте доступ к кабинету только уполномоченному лицу.
3. Подтвердить → проверить договор и заполнить пустые условия → подписать оба экземпляра и акт → «Авто выдано».
4. При возврате заполнить акт → «Авто возвращено».
5. Внести фактически полученную сумму аренды без залога. Это управленческий учёт, не кассовый чек и не бухгалтерская система.
6. Скачать Excel. Если файл открыт в Excel и Windows блокирует замену, закрыть его и повторить скачивание или `npm run export`.
7. Отменённые и истёкшие анкеты можно удалить. Удаление затрагивает текущую базу, локальные сгенерированные файлы и актуальный отчёт; скачанные копии, старые резервные копии и переписка в Telegram требуют отдельной процедуры.

## 6. Эксплуатация

- Не публиковать `.env`, `data/`, `private/`, резервные копии. .gitignore — дополнительный барьер, не замена контроля.
- Пароль владельца хранится в памяти вкладки; обновление страницы потребует входа. Ввести индивидуальные роли и MFA при появлении сотрудников.
- Резервировать SQLite корректно (backup API / остановка процесса), файлы и DATA_KEY отдельно; проверить восстановление. Не копировать только .sqlite во время записи без учёта WAL.
- Установить график обновлений Node.js и npm-зависимостей. Контрольные команды: npm ci, npm test, npm audit --omit=dev.
- Отчёт отражает все заявки, статистику по месяцам выдачи и полученные суммы. В интерфейсе до 1000 последних заявок; полный набор — в Excel.
- Обновление отчёта раз в час не является точным финансовым мониторингом. Истёкшие брони освобождаются и при следующем запросе.
- Если ошибка генерации файла произошла после сохранения анкеты, заявка остаётся в базе; пересоздать файлы через npm run export.

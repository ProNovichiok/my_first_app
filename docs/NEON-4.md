# Балтик Драйв 4.0 — Node.js и Neon

Код: https://github.com/ProNovichiok/my_first_app
Сайт: https://pronovichiok.github.io/my_first_app/
Кабинет владельца: https://pronovichiok.github.io/my_first_app/admin.html
API: https://br-dawn-haze-bajuloc6-balticdrive.compute.c-8.eu-central-1.aws.neon.tech

Фронтенд работает на GitHub Pages, сервер и webhook Telegram — в Neon Functions на Node.js 24. Компьютер владельца для работы бота не нужен. Старые версии доступны в истории GitHub; в текущем проекте используется только Node.js.

## Режим данных

Это учебная версия. Не вводите реальные паспортные данные и права. Сервер запрещает DEMO_MODE=false. Для реального проката потребуются размещение и обработка данных в подходящей инфраструктуре, реальные реквизиты, проверка условий и документов. Изменение одного переключателя не делает проект готовым к реальному приёму документов.

Заявка с сайта хранится в PostgreSQL, после Telegram заполняется синтетической анкетой. Идентификатор Telegram и анкета шифруются AES-256-GCM. DATA_KEY хранится только в секретах сервера; потеря ключа лишит доступа к зашифрованным полям. Настоящие документы бот не просит. Старая SQLite-база остаётся на компьютере и автоматически в облако не переносится.

## Кабинет и файлы

Ссылки на кабинет нет в навигации. Адрес не является защитой: API проверяет длинный ADMIN_TOKEN. Ключ вводится в кабинете и хранится в памяти вкладки, не в localStorage. В GitHub находятся только публичный адрес API и исходники.

В кабинете: поиск, статусы, полученная аренда отдельно от залога, договор в двух экземплярах с актами, отчёт .xlsx с тремя листами. Договор и Excel формируются по запросу и скачиваются на компьютер. После изменения заявки скачайте актуальные файлы повторно. Файлы не сохраняются на эфемерном диске Functions; Object Storage для этих операций не требуется. Кабинет показывает последние 1000 записей, Excel — последние 10000, что явно отмечено в отчёте. При росте базы нужен экспорт по периодам.

## Бесплатные лимиты, проверено 1 ноября 2026

- PostgreSQL: 1 ГБ на проект, 100 CU-часов в месяц, до 2 CU; остановка после 5 минут бездействия.
- Functions: 1 млн вызовов, 10 active capacity-hours и 400 waiting capacity-hours на проект.
- Runtime: Node.js 24, фиксированные 2048 MiB на изолят; уменьшить память настройкой нельзя.
- 100 одновременных вызовов на аккаунт по умолчанию; пул приложения ограничен двумя соединениями на изолят.
- Исходящий трафик Free: 5 ГБ на проект. Фотографии и анимации раздаются GitHub Pages и не расходуют этот трафик Neon.

Это квоты, а не гарантия бесплатной работы при любой посещаемости. Проверяйте Usage в Neon. Бот использует webhook без getUpdates, сервер не делает постоянных фоновых запросов. Каталог и /health не обращаются к базе. Excel строится только при нажатии экспорта.

Официальные источники: https://neon.com/pricing и https://neon.com/docs/compute/functions/reference/runtime-limits

## Локальный запуск (не обязателен для облака)

Установите Node.js 24 с npm. Затем:

```text
npm ci --ignore-scripts --no-audit --no-fund
node scripts/setup-node.mjs
```

Заполните .env.node: DATABASE_URL, ADMIN_TOKEN (32+ символа), DATA_KEY (64 hex), BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET (32+ символа). Для локального фронтенда задайте PUBLIC_URL=http://localhost:3003. Для облака PUBLIC_URL — адрес GitHub Pages. Не включайте секреты в скриншоты, issue или коммиты.

```text
npm run migrate
npm test
npm start
```

Миграция создаёт только схему baltic_v4, не удаляет существующие данные. Проверка на настоящем PostgreSQL с откатом: node --env-file=.env.node scripts/check-neon.mjs.

## Публикация обновлений

После push GitHub Actions проверяет Node-сервер и собирает dist/function.zip. GitHub Pages публикуется автоматически. Для API нужно отдельно развернуть новую функцию через подключённый Neon или CLI/API; один push не обновляет функцию автоматически.

```text
npm run build
node --env-file=.env.node scripts/deploy-neon.mjs
```

Для второй команды дополнительно требуется NEON_API_KEY в окружении. Архив содержит один index.mjs. Секреты передаются отдельно от архива, DATABASE_URL Neon подставляет сам. Конфигурация проекта и ветки: config/neon-project.json.

После первой публикации:

```text
node --env-file=.env.node scripts/telegram-webhook.mjs set https://ВАША-ФУНКЦИЯ
node --env-file=.env.node scripts/telegram-webhook.mjs check
```

Не запускайте polling одновременно с webhook. Переключение не удаляет ожидающие сообщения. Проверка webhook не отправляет сообщения пользователям.

## Состав

server/ — конфигурация, PostgreSQL, заявки, шифрование, Telegram, договоры и XLSX.
functions/index.mjs — входная точка Neon.
public/ — фронтенд; pages/ — подготовленная публикация GitHub Pages.
scripts/ — сборка, миграция, проверки и публикация.

Производственные зависимости: pg и fflate. esbuild используется только при сборке. Express, Java, постоянный процесс polling и файловое хранилище для отчётов не нужны.
